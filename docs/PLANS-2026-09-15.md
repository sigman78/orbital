## Long horizon

Where the renderer is going. Three threads that meet in the middle: the belt
moves to CPU-owned state so physics can drive it, the bodies get the same
visibility and level treatment the belt already has, and the frame loop is
rearranged so culling and state production run ahead of rendering. The
threads share data structures, so the order below keeps each step small and
measurable.

### Vision

- The CPU owns the state of everything that moves: bodies and rocks in one
  structure-of-arrays store with the same integrator interface, bodies being a
  few entries with mass and their own draw path. Rocks can be spawned and
  destroyed. Motion can be anything the physics wants; the renderer only reads
  positions and previous positions.
- The GPU is the fine stage: it refines visibility per rock, chooses levels,
  lights the splats and draws. It never recomputes motion.
- Every drawn thing carries its motion, so temporal AA reprojects per pixel and
  needs no clipping tricks to hide moving rocks.
- Visibility is one stage with two granularities: the CPU rejects bodies and
  belt sectors from its own state, the GPU refines rocks. Both read one
  frustum, one occluder set, one cull camera, which the freeze switch can hold.
- Bodies are drawn at the cost their size deserves: a depth pre-pass so overlap
  is free, shader tiers that fade detail terms without changing lighting, and
  impostor discs below a few pixels.
- Culling and state production run one frame ahead of rendering, so the frame's
  critical path is the draw.

### Thread A: belt motion on the CPU

| # | Step | Notes | Effort |
|---|------|-------|--------|
| L.1 | Per-rock state buffer written by the CPU | SoA position and previous position; the static record keeps radius, seeds and class. The cull, light-map splat and disc bake read state instead of recomputing the closed form. Staging copy into device memory per frame, not host-visible reads across the bus (the BAR heap is at its edge). First cut writes the same closed-form motion, so the image is unchanged and the upload cost is measured honestly (12.5 MB per frame at 520k rocks). | one day |
| L.2 | Integration pass with SIMD and jobs | One sequential streaming pass per frame that integrates, writes the state and sets sector flags; SIMD lanes, a job split across cores, the far tail optionally across frames. Deterministic fixed step so captures and benchmarks stay reproducible. The data does not fit in cache at this count; the pass is bandwidth bound, so everything happens in the one sweep. | two days |
| L.3 | Motion vectors for rocks and bodies | Previous position through the instance record to a velocity target, per-pixel reprojection in TAA. Replaces the moving-clip workaround; bodies get rotation motion for free. | one to two days |
| L.4 | Sector partition and coarse CPU cull | Belt sorted by band and angular sector with slack for spawns; the CPU rejects sectors in bulk, the GPU refines. Per-rock CPU culling stays out: the GPU pass is 0.19 ms and the splat lighting needs textures. | one day |
| L.5 | Unified state model with physics | Bodies and rocks in the same store and integrator; spawn and destroy as appends and holes; the physics model of the user's choosing on top. | open |

### Thread B: bodies at the cost their size deserves

| # | Step | Notes | Effort |
|---|------|-------|--------|
| L.6 | Body depth pre-pass | Order independent, so a giant in front of its belt or another body costs nothing to shade twice. Measured with the Bodies and Rocks children before and after; draw-order tricks were rejected because the occluder set changes with the view. Needs I.2. | one day |
| L.7 | Fast-path body shader tiers | Chosen by projected size. No-pop rule: lighting and tone terms stay identical across tiers, only detail terms (normal maps, clouds, night lights, ocean specular, band detail) fade with the texel-to-pixel ratio, so the switch is invisible. Earth first, then the gas giant, then airless bodies. | two days |
| L.8 | Far-tier body impostors | Below a few pixels a body is a disc of its average colour with the phase shading, drawn as a billboard; no surface pass at all. The smallest tier of L.7. | one day |

### Thread C: the frame loop

| # | Step | Notes | Effort |
|---|------|-------|--------|
| L.9 | Async cull one frame ahead | Double-buffered cull scratch, frustum padded for one frame of motion, camera cuts fall back to a same-frame cull. With L.1 the CPU produces next frame's state and sector list together. After L.6 to L.8 so its padding covers the body paths too. | one day |

### Order across threads

1. I.1 and I.2, so readings are legible and bodies are culled before anything is measured.
2. L.6 with its confirming run (I.3 alongside).
3. L.1 then L.3, since motion vectors also settle I.6.
4. L.7 and L.8 together.
5. L.9 once the body paths are settled.
6. L.2, L.4 and L.5 when the physics model is ready; L.1 already gives it the buffer to write into.
